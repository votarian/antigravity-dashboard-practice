# 마크인포 문제 해결형 OKR 시스템 화면흐름도

이 문서는 [PRD](./PRD.md), [기존 MVP 기획서](./local-okr-mvp-design.md), [시장조사 종합본](../.omo/ulw-research/20260902-okr-market-research/SYNTHESIS.md)을 기준으로 MVP의 화면 이동과 핵심 운영 흐름을 정의한다.

## 1. 전체 화면 구조와 전역 이동

```mermaid
flowchart TD
    Login[로그인] --> Home[홈 대시보드]

    Home --> ProblemList[문제 백로그]
    Home --> GoalBoard[목표 보드]
    Home --> CheckIn[체크인 작성]
    Home --> WeeklyList[주간 보고]
    Home --> MonthlyList[월간 리뷰와 회의록]
    Home --> CloseoutList[Closeout과 OKR 파티]
    Home --> MyWork[내 협업]
    Home --> Admin[관리자]

    ProblemList --> ProblemDetail[문제 상세와 선정 결정]
    GoalBoard --> GoalDetail[목표 상세]
    GoalDetail --> CheckIn
    GoalDetail --> Feedback[피드백과 댓글]
    GoalDetail --> Dependency[협업과 의존성]
    WeeklyList --> WeeklyEditor[주간 보고 작성]
    MonthlyList --> MeetingDetail[회의록 상세]
    CloseoutList --> CloseoutDetail[주기 마감 상세]
    MyWork --> GoalDetail

    Admin --> UserTeam[사용자와 팀 관리]
    Admin --> CycleAdmin[주기 preset과 일정 관리]
    Admin --> SlackAdmin[Slack 설정]
    Admin --> AuditLog[감사 로그]
```

## 2. 문제 백로그에서 OKR 선정까지

```mermaid
flowchart TD
    ProblemList[문제 백로그] --> NewProblem[문제 등록]
    ProblemList --> ProblemDetail[문제 상세]

    NewProblem --> ProblemDetail
    ProblemDetail --> Evidence[근거와 참고 링크]
    ProblemDetail --> Feedback[리더와 개발 피드백]
    ProblemDetail --> Priority[우선순위 설정]
    ProblemDetail --> Decision[선정 결정]

    Decision --> Accepted{OKR로 선정?}
    Accepted -->|선정| ObjectiveDraft[Objective 초안 작성]
    ObjectiveDraft --> Alignment[팀과 리더 합의]
    Alignment --> KRForm[KR와 책임자 설정]
    KRForm --> GoalBoard[활성 목표 보드]

    Accepted -->|보류| Deferred[보류와 다음 검토일 기록]
    Accepted -->|거절| Rejected[거절 사유 기록]
    Accepted -->|중복| Duplicate[대표 문제와 연결]
    Deferred --> ProblemList
    Rejected --> Archive[문제 아카이브]
    Duplicate --> ProblemList
```

## 3. 목표 실행·체크인·주간 Slack 보고

```mermaid
flowchart TD
    Home[홈 또는 목표 상세] --> CheckInForm[체크인 작성]
    CheckInForm --> Progress[값과 상태 입력]
    Progress --> Context[성과, 이슈, 다음 행동 입력]
    Context --> Help{도움 요청 또는 의존성?}
    Help -->|예| Dependency[협업자 또는 의존성 연결]
    Help -->|아니오| CheckInHistory[체크인 이력과 추이]
    Dependency --> CheckInHistory

    CheckInHistory --> WeeklyEditor[주간 보고 작성]
    WeeklyEditor --> WeeklyPreview[Slack 전송 미리보기]
    WeeklyPreview --> Confirm{사용자 전송 확인?}
    Confirm -->|아니오| WeeklyEditor
    Confirm -->|예| SlackSend[지정 Slack 채널로 전송]
    SlackSend --> DeliveryResult{전송 결과}
    DeliveryResult -->|성공| Sent[전송 이력과 메시지 ID 저장]
    DeliveryResult -->|실패| Failed[실패 원인 표시]
    Failed --> Retry{사용자가 재전송?}
    Retry -->|예| WeeklyPreview
    Retry -->|아니오| Draft[보고 초안 보존]

    Sent --> Feedback[Slack 링크를 통한 피드백과 목표 댓글]
```

## 4. 월간 리뷰·회의록·closeout

```mermaid
flowchart TD
    MonthlyList[월간 리뷰와 회의록 목록] --> MeetingForm[회의록 작성]
    MeetingForm --> MeetingInfo[일시, 참석자, 안건 입력]
    MeetingInfo --> ReviewContent[잘 된 KR, 어려움, 다음 계획 입력]
    ReviewContent --> Decisions[결정, 위험, 학습 기록]
    Decisions --> ActionItem[액션 아이템 생성]
    ActionItem --> GoalLink[문제, 목표, KR, 주간 보고 연결]
    GoalLink --> MonthlyList

    MonthlyList --> CycleHealth[주기 중간 건강 점검]
    CycleHealth --> Active[주기 Active 유지]
    Active --> CloseoutStart[Closeout 시작]
    CloseoutStart --> FinalResult[KR 최종값과 문제 결과 확정]
    FinalResult --> CarryDecision{미완료 항목 처리}
    CarryDecision -->|중단| StopWork[중단 사유 기록]
    CarryDecision -->|계속| Successor[다음 주기 후속 목표 연결]
    CarryDecision -->|재범위화| Rescope[새 범위와 책임자 합의]
    CarryDecision -->|상시 업무 전환| Operations[상시 업무로 전환]

    StopWork --> Closed[주기 Closed]
    Successor --> Closed
    Rescope --> Closed
    Operations --> Closed
    Closed --> Party[OKR 파티 기록과 비순위형 인정]
    Party --> NextCycle[다음 주기 Draft 또는 Alignment]
```

## 5. 권한과 협업 화면 접근

```mermaid
flowchart LR
    Admin[관리자] --> AdminScreens[조직, 사용자, 주기, Slack, 감사 로그]
    Leader[팀 리더] --> TeamViews[팀 문제 검토, 팀 목표, 월간 리뷰]
    Member[구성원] --> MemberViews[문제 제안, 체크인, 주간 보고, 회의록]
    Contributor[타팀 협업자] --> CollaborationViews[연결된 목표, 댓글, 배정 액션]

    TeamViews --> GoalDetail[목표 상세]
    MemberViews --> GoalDetail
    CollaborationViews --> GoalDetail
    GoalDetail --> Visibility{권한 확인}
    Visibility -->|소유자 또는 리더| EditGoal[목표와 상태 수정]
    Visibility -->|협업자| Contribute[댓글, 배정 체크인, 액션 아이템]
    Visibility -->|관찰자| ReadOnly[읽기 전용]
```

## 화면 흐름 원칙

- 사용자는 홈에서 **내 소속 팀**, **내 책임 목표**, **협업 중인 목표**를 구분해 진입한다.
- 문제는 탐색 단계에서 목표 연결 없이 존재할 수 있으며, 선정 시점에만 Objective 또는 KR과 연결한다.
- Slack 전송은 자동 실행되지 않는다. 미리보기와 사용자의 최종 확인이 항상 필요하다.
- 체크인·주간 보고·회의록은 과거 기록을 덮어쓰지 않고 이력으로 남긴다.
- closeout 이후 원 주기는 읽기 전용이며, 이월은 새 주기 목표와의 연결로 표현한다.
- 개인 OKR은 팀별 opt-in이다. 일반 업무는 팀 KR의 책임자 또는 협업자로 표현한다.

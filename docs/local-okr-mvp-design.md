# 사내 로컬 OKR 시스템 MVP 기획서

## 1. 목적과 운영 전제

마크인포 구성원이 목표를 수립하고, 매주 진행 상황을 공유하며, 리더가 피드백과 정기 리뷰를 남길 수 있는 사내 전용 OKR 시스템을 구축한다.

- 시스템은 사내 서버 컴퓨터에 설치한다.
- 사내 직원은 사내망 URL로 접속한다.
- 원격 근무자 5~6명은 초대형 사설망을 통해서만 접속한다.
- 일반 인터넷에는 시스템 포트를 공개하지 않는다.
- Slack에는 승인된 `주간 보고 OKR` 채널로만 주간 보고를 전송한다.

## 2. MVP 범위

### 포함

1. 사용자·조직·권한
   - 관리자, 팀 리더, 구성원 역할
   - 팀과 소속 구성원 관리
   - 계정별 로그인 및 역할 기반 접근 제어

2. OKR 목표 보드
   - 회사 목표, 팀 목표, 개인 목표의 상하위 연결
   - 목표 제목, 설명, 기간, 담당자, 상태, 난이도, 진행률 관리
   - 목표 생성·수정 시 리더 승인 흐름

3. 체크인과 피드백
   - 구성원의 주기적 진행률, 성과, 이슈, 다음 행동 기록
   - 리더의 댓글형 코칭·피드백
   - 목표별 체크인 이력 조회

4. 정기 리뷰
   - 셀프 리뷰와 리더 리뷰
   - 등급/점수와 서술형 피드백
   - 리뷰 대상·작성 상태·마감 현황 조회

5. 주간 보고와 Slack 전송
   - 이번 주 성과, 목표 진행률, 이슈/도움 요청, 다음 주 계획 작성
   - 작성자가 미리보기 후 `Slack으로 전송`을 직접 실행
   - 전송 성공/실패 및 전송 시각을 시스템에 기록

6. 회의록
   - 일시, 참석자, 안건, 논의 내용, 결정 사항, 액션 아이템 작성
   - 액션 아이템 담당자와 기한 지정
   - 회의록과 관련 OKR 목표 연결

7. 기본 리포트
   - 조직·개인별 목표 진행률
   - 기간별 체크인 및 리뷰 결과
   - 개인별 목표, 피드백, 주간 보고 이력

### 제외

- 외부 고객용 공개 페이지
- 모바일 앱
- 급여·인사 시스템 자동 연동
- 자동 Slack 발송 및 AI 평가
- 복잡한 다단계 평가 보정·성과급 산정

## 3. 사용자 역할

| 역할 | 주요 권한 |
| --- | --- |
| 관리자 | 사용자·조직·권한, 리뷰 주기/템플릿, Slack 설정, 전체 리포트 관리 |
| 팀 리더 | 팀 목표 승인, 팀원 체크인 코칭, 팀 리뷰 작성·확인 |
| 구성원 | 개인 목표·체크인·주간 보고·회의록 작성, 셀프 리뷰, 배정된 정보 조회 |

## 4. 핵심 업무 흐름

```text
관리자: 조직/사용자/리뷰 주기 설정
  ↓
리더·구성원: 회사 → 팀 → 개인 목표를 연결해 수립
  ↓
구성원: 매주 체크인 및 주간 보고 작성
  ↓
작성자: 내용을 확인하고 Slack 전송 버튼을 눌러 지정 채널에 게시
  ↓
리더: 목표·체크인을 확인하고 피드백 또는 정기 리뷰 작성
  ↓
관리자·리더: 조직/개인 리포트에서 진행률과 리뷰 이력 확인
```

회의록은 어느 단계에서나 작성할 수 있으며, 결정 사항과 액션 아이템을 특정 OKR에 연결한다.

## 5. 화면 구성

1. 로그인
2. 홈 대시보드: 내 목표, 이번 주 체크인, 미작성 주간 보고, 받은 피드백
3. 목표 보드: 계층형 목표 목록, 상태·진행률·기간 필터, 목표 상세 패널
4. 목표/체크인 작성 화면: 목표 내용·기간·담당자·난이도·진행률·성과·이슈 입력
5. 주간 보고: 작성 폼, Slack 미리보기, 전송 이력
6. 정기 리뷰: 대상 목록, 셀프/리더 리뷰 작성, 제출 상태
7. 회의록: 회의 정보, 결정 사항, 액션 아이템, 연결 목표
8. 리포트: 회사/팀/개인별 진행률과 리뷰·피드백 이력
9. 관리자: 사용자·팀·리뷰 템플릿·Slack 연동 설정

## 7. 기술 및 배포 설계

### 애플리케이션

- 단일 웹 애플리케이션과 PostgreSQL 데이터베이스를 Docker Compose로 함께 운영한다.
- 서버 운영체제는 Ubuntu LTS를 우선 권장한다. 기존 서버가 Windows라면 Docker가 안정적으로 운영되는지 사전 점검 후 배포한다.
- 데이터와 설정은 Docker 볼륨 및 서버의 접근 제한된 설정 파일로 분리한다.

### 접속 보안

- 사내 서버는 인터넷 포트 포워딩을 하지 않는다.
- 서버와 지정 사용자 PC에 Tailscale 등 초대형 사설망 클라이언트를 설치한다.
- 보안망 초대는 관리자만 수행하고, 허용 사용자·기기를 개별 승인한다.
- 방화벽은 사내망과 사설망에서의 웹 접속만 허용한다.
- 애플리케이션은 별도의 계정 로그인과 역할 권한을 적용한다.
- 사용자 퇴사 또는 역할 변경 시 OKR 계정 비활성화와 사설망 초대 철회를 함께 처리한다.

### Slack 연동

- MVP는 지정된 단일 `주간 보고 OKR` 채널로의 단방향 전송만 제공한다.
- 전용 Incoming Webhook을 사용하며, 웹훅 URL은 서버 비밀 설정으로만 저장한다.
- 사용자는 전송 전 내용을 미리보기로 확인하고 직접 전송한다.
- 시스템은 전송 결과를 저장하며 실패 시 재전송 버튼을 제공한다.
- Slack 메시지 삭제·수정·채널 읽기 권한은 요청하지 않는다.

## 8. 보안·운영 기준

- 비밀번호는 단방향 해시로 저장하며 평문을 저장하지 않는다.
- Slack 웹훅 URL과 데이터베이스 비밀번호는 소스 코드·Git 저장소·화면에 기록하지 않는다.
- 주간 자동 데이터베이스 백업과 월 1회 복구 점검을 실시한다.
- 감사 로그는 Slack 전송, 권한 변경, 목표/리뷰 상태 변경을 남긴다.
- Slack 전송은 외부 시스템 게시 행동이므로 사용자 클릭이 있는 경우에만 실행한다.

## 9. MVP 완료 기준

1. 관리자 1명, 리더 1명, 구성원 여러 명이 각각 로그인할 수 있다.
2. 회사·팀·개인 목표를 연결하고 체크인과 피드백을 남길 수 있다.
3. 구성원이 주간 보고를 작성하고 승인된 Slack 채널에 직접 전송할 수 있다.
4. 회의록의 결정 사항과 액션 아이템을 목표에 연결할 수 있다.
5. 리더가 정기 리뷰를 작성하고 구성원·팀별 결과를 확인할 수 있다.
6. 사내망과 초대된 원격 근무자만 시스템에 접속할 수 있다.
7. 일반 인터넷에서는 시스템 URL에 접속할 수 없다.

## 10. 구현 우선순위

1. 접속 보안, 사용자/조직/권한, 데이터베이스 기반
2. 목표 보드와 체크인
3. 주간 보고와 Slack 직접 전송
4. 회의록·액션 아이템
5. 정기 리뷰와 기본 리포트

이 순서는 핵심 OKR 운영을 먼저 안정화하고, 외부 게시 기능은 명시적 사용자 전송으로 제한하며, 복잡도가 높은 평가 리포트는 마지막에 추가하기 위한 것이다.
